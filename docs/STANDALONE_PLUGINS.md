# Standalone Plugins: Dual Build Mode Guide

This document describes how to compile, run, and package individual plugins as standalone Compose Desktop applications in the Plugin Toolkit repository.

---

## 1. Overview & Architecture

Every plugin in this repository is built on top of `:plugin-api` without direct dependencies on Compose Multiplatform or GUI frameworks. To enable testing, distributing, or running an individual plugin as an independent desktop application, the repository provides a **Dual Build Mode**:

| Mode | Target Artifact | Dependencies | Primary Use Case |
| :--- | :--- | :--- | :--- |
| **Pure Plugin Mode** (Default) | `.jar` | Pure JVM (`:plugin-api` + business logic) | Production plugin distribution, marketplace uploading, multi-plugin desktop app |
| **Standalone Mode** | Runnable desktop app or native installer | `:apps:standaloneRunner` + Compose Desktop + target plugin | Local GUI testing, standalone app distribution, single-purpose utilities |

---

## 2. Running a Plugin in Standalone Mode

### Running `completeExample`
You can launch the complete reference plugin directly in standalone mode using the Gradle convenience task:
```bash
./gradlew :plugins:completeExample:run
```
Alternatively, invoke the standalone runner module directly:
```bash
./gradlew :apps:standaloneRunner:run
```

### Running Any Other Plugin
By default, `:apps:standaloneRunner` targets `:plugins:completeExample`. You can run any other plugin module by specifying the `targetPlugin` project property:
```bash
./gradlew :apps:standaloneRunner:run -PtargetPlugin=:plugins:minimalExample
```

### Running from a Compiled JAR File
You can also launch the standalone host against an arbitrary external plugin JAR using the `--plugin-jar` flag:
```bash
./gradlew :apps:standaloneRunner:run --args="--plugin-jar /path/to/my-plugin.jar"
```
Or via JVM system property:
```bash
./gradlew :apps:standaloneRunner:run -Dplugin.jar="/path/to/my-plugin.jar"
```

## 3. Standalone User Interface Features

The standalone desktop window is powered by `SinglePluginRunnerView` and provides a lightweight, focused execution environment:

1. **Plugin Header & Action Group:**
   - Displays plugin name, version badge, description, and minimum memory requirement.
   - Includes a unified **Action Button Group** (`ToolkitButtonGroup`):
     - **Setup Action:** If the plugin declares a setup handler (`@PluginSetup` / `hasSetupHandler`), displays **Run Setup** (or **Rerun Setup** if already completed), with inline progress spinner when running.
     - **Settings Action:** Opens the plugin configuration dialog (`PluginSettingsDialog`).

3. **Capability Selector:**
   - Left-hand rail listing all capabilities declared in the manifest.
   - Real-time search filter and lock status indicators.

4. **Execution Parameters & Tester:**
   - Dynamic parameter input cards with type-safe fields (strings, numbers, booleans, file pickers).
   - Autogenerated pattern resolution (e.g. `{inputPath}/output.json`).
   - Actions to **Set as Default**, **Reset to Default**, and **Execute Capability**.

5. **Live Job Results & Terminal:**
   - Displays active and historical `JobResultCard` components.
   - Shows live progress bar, peak memory usage, execution duration, and output results.
   - Includes an integrated, resizable terminal console with logs and search.
   - Job control actions: cancel, pause, resume, clear, and delete.

## 4. Packaging Native Standalone Distributions

The standalone runner supports packaging native installers and portable binaries for Windows, macOS, and Linux:

### Distributable Binaries (Unpacked Folder)
To build an unpacked, runnable native distribution folder containing the native executable (`<AppName>.exe` on Windows), bundled JRE runtime (no Java installation required), and plugin libraries:
```bash
# For minimalExample:
./gradlew :plugins:minimalExample:createDistributable

# For completeExample:
./gradlew :plugins:completeExample:createDistributable

# For any plugin via project property:
./gradlew :apps:standaloneRunner:createDistributable -PtargetPlugin=:plugins:myPlugin
```
The output is generated in:
`apps/standaloneRunner/build/compose/binaries/main-release/app/<AppName>/` (e.g. `MinimalExample/MinimalExample.exe`).

### Portable ZIP Distribution
To build a portable self-contained ZIP distribution containing the native app, bundled JRE, and `.portable` marker:
```bash
# For minimalExample:
./gradlew :plugins:minimalExample:packageStandalonePortable

# For completeExample:
./gradlew :plugins:completeExample:packageStandalonePortable

# For any plugin via project property:
./gradlew :apps:standaloneRunner:packagePortableZip -PtargetPlugin=:plugins:myPlugin
```
The output is generated in:
`apps/standaloneRunner/build/compose/binaries/main/portable/<AppName>-<os>-portable-<version>.zip` (e.g. `MinimalExample-windows-portable-2.1.0.zip`).

### Native Installers (MSI, EXE, DMG, DEB)
To package an installer for the current OS:
```bash
./gradlew :plugins:minimalExample:packageStandalone
# or
./gradlew :apps:standaloneRunner:packageDistributionForCurrentOS -PtargetPlugin=:plugins:minimalExample
```

## 5. Adding Standalone Support to Custom Plugins

To add standalone runner tasks to a custom plugin, add the following snippet to its `build.gradle.kts`:

```kotlin
// --- Dual Build Mode: Standalone Desktop Runner Tasks ---
tasks.register("run") {
    group = "application"
    description = "Runs this plugin as a standalone desktop app via :apps:standaloneRunner"
    dependsOn(":apps:standaloneRunner:run")
}

tasks.register("createDistributable") {
    group = "distribution"
    description = "Generates the unpacked, runnable native standalone application directory"
    dependsOn(":apps:standaloneRunner:createDistributable")
}

tasks.register("packageStandalone") {
    group = "distribution"
    description = "Packages this plugin as a standalone native desktop installer/app"
    dependsOn(":apps:standaloneRunner:packageDistributionForCurrentOS")
}

tasks.register("packageStandalonePortable") {
    group = "distribution"
    description = "Packages this plugin as a standalone portable ZIP distribution"
    dependsOn(":apps:standaloneRunner:packagePortableZip")
}
```

Because tasks link to `:apps:standaloneRunner`, the plugin's own `compileKotlin`, `jar`, and `build` tasks remain 100% clean and pure without any Compose Desktop or GUI dependencies.

## 6. Data Folder Isolation (`StandaloneSystemConfig`)

To prevent standalone applications from conflicting with or overwriting the main desktop application's data or each other:
- Each standalone application runs under `StandaloneSystemConfig(pluginId)`.
- Persistent data, settings, jobs, logs, and caches are scoped to dedicated isolated directories:
  - **Standard Mode:**
    - Windows AppData: `%APPDATA%/PluginToolkit/standalone/<pluginId>/`
    - Windows Cache: `%LOCALAPPDATA%/PluginToolkit/standalone/<pluginId>/cache/`
    - Linux/macOS: `~/.plugintoolkit/standalone/<pluginId>/`
  - **Portable Mode (with `.portable` marker):** `<baseDir>/data/`
- Host autostart and Windows registry auto-run modifications are disabled for all standalone runners.
- The main desktop application's data directory (`PluginToolkit/`) remains completely untouched.
