# Plugin Core Reference

This document provides a detailed reference for core plugin architecture, annotations, parameters, settings, validation, and dynamic parameters.

---

## 1. Plugin Entry & Metadata

Every plugin must define a main class annotated with `@PluginInfo`. The toolkit's KSP processor generates the necessary `PluginEntry` and `PluginModuleProvider` boilerplate.

```kotlin
@PluginInfo(
    id = "my-plugin",
    name = "My Awesome Plugin",
    version = "1.0.0",
    description = "Does amazing things."
)
class MyPlugin(val settings: MyPluginSettings) : DataProcessor {
    // Business logic
}
```

### Constructor Injection & Settings
Plugins separate settings into an immutable `data class`. KSP generates bindings to automatically populate the settings class via Koin dependency injection:

```kotlin
data class MyPluginSettings(
    @PluginSetting(
        description = "Service Endpoint",
        regex = "^https?://.*"
    ) val endpoint: String = "https://api.example.com",

    @PluginSetting(
        description = "Timeout in seconds",
        minValue = 1.0,
        maxValue = 120.0
    ) val timeoutSeconds: Int = 30,

    @PluginSetting(
        description = "API Token",
        secret = true,
        required = true
    ) val apiToken: String = ""
)
```

#### Settings Metadata Attributes:
- `description` (String): Display label/description in settings UI.
- `required` (Boolean): If true, blocks execution until the user supplies a value.
- `secret` (Boolean): Masks UI input and securely encrypts the value on disk using native OS secure storage (DPAPI on Windows, Keychain on macOS, Secret Service on Linux).
- `regex` (String): Regular expression pattern used to validate inputs.
- `minValue` / `maxValue` (Double): Numerical boundaries.
- `multiSelect` (Boolean): Enables multi-select dropdown menu (automatically true for Enum collections).
- `minChoices` / `maxChoices` (Int): Minimum and maximum number of choices allowed for multi-select.

## 2. Capabilities

Capabilities are operations exposed by the plugin to the host application or flow canvas. Capabilities are annotated with `@Capability`.

```kotlin
@Capability(
    name = "Process Text",
    description = "Transforms text input",
    supportsPause = false,
    context = CapabilityContext.ANY // ANY, FLOW_ONLY, or STANDALONE_ONLY
)
suspend fun processText(
    @CapabilityParam("The input string") input: String,
    @CapabilityParam("Optional multiplier", defaultValue = "1") count: Int = 1
): String {
    return input.repeat(count)
}
```

### Capability Execution Context (`CapabilityContext`)
- `CapabilityContext.ANY` (default): Available for direct standalone execution and within the Flow Editor canvas.
- `CapabilityContext.FLOW_ONLY`: Scoped strictly as a node in flows; hidden from standalone execution sidebars and runner views. Direct standalone execution throws `IllegalStateException`.
- `CapabilityContext.STANDALONE_ONLY`: Available only in direct plugin runner views; hidden from the flow palette.

### Parameter Annotations

| Annotation | Purpose | Inferred Host Permission |
| :--- | :--- | :--- |
| `@CapabilityParam` | Standard parameter input (text, numeric, boolean, enum, list, object). | None |
| `@CapabilityInput` | Marks a parameter representing an input file or folder path. | `readsFiles = true` (implicit read permission) |
| `@CapabilityOutput` | Marks a parameter representing an output file or folder path. | `writesFiles = true` (implicit write permission) |

#### `@CapabilityOutput` Properties:
- `autogeneratedPattern`: A template string (e.g., `{inputPath}/../../converted.txt`) dynamically calculating the output path based on other inputs.
- `isDestructive`: When `true`, warns users that existing target files may be overwritten.
- `semanticTypes`: Array of semantic types (e.g. `["file/txt"]`).

### Parameter Validation Constraints

Parameters annotated with `@CapabilityParam` support validation enforced at both the UI level (real-time error states) and runner level (pre-execution check):

| Constraint | Type | Description |
| :--- | :--- | :--- |
| `required` | Boolean | Disallows empty values; field shows "Required". |
| `regex` | String | Regular expression pattern the value must match. |
| `minLength` | Int | Minimum allowed string length. |
| `maxLength` | Int | Maximum allowed string length. |
| `minValue` | Double | Minimum numeric value (for `Int`, `Long`, `Double`, `Float`). |
| `maxValue` | Double | Maximum numeric value (for `Int`, `Long`, `Double`, `Float`). |
| `multiSelect` | Boolean | Enables multi-select dropdown. Auto-inferred for Enum `Collection`, `Set`, or `List`. |
| `minChoices` | Int | Minimum number of items that must be selected. |
| `maxChoices` | Int | Maximum number of items that can be selected. |

**Note on Collections**: Parameter types accept generic `Collection<T>`, `List<T>`, `Set<T>`, and `Iterable<T>`. Regex and length constraints are validated for **each individual item** in the collection.

### Multi-Selectable Enum Collections
Declaring a parameter or setting as `Collection<MyEnum>`, `List<MyEnum>`, or `Set<MyEnum>` (or adding `multiSelect = true`) causes the host UI to render a multi-select dropdown menu with checkboxes. The selected items are serialized as a JSON array (e.g. `["OPTION_A", "OPTION_B"]`).

## 3. Advanced & Dynamic Parameters

### 1. Advanced Parameters (`isAdvanced = true`)
Parameters marked with `isAdvanced = true` are collapsed by default into an **Advanced Options** drawer in host dialogs and node inspectors:

```kotlin
@CapabilityParam(
    description = "Random seed (-1 for random)",
    defaultValue = "-1",
    isAdvanced = true
) seed: Long = -1L
```

### 2. Dynamic Conditions (`@DependsOn`, `@DependsOnAny`, `@DependsOnAll`)
Dynamic parameters appear only when specific conditions are met in other parameters, plugin settings, or feature locks:

```kotlin
@Capability(name = "Render Scene")
fun renderScene(
    @CapabilityParam(description = "Engine", defaultValue = "EEVEE")
    engine: String,

    // Visible only when engine == "CYCLES"
    @CapabilityParam(description = "Sample count", defaultValue = "128")
    @DependsOn(param = "engine", value = "CYCLES")
    cyclesSamples: Int = 128,

    // Visible when highPrecision setting is true AND engine != EEVEE
    @CapabilityParam(description = "Bounces", defaultValue = "12", isAdvanced = true)
    @DependsOn(setting = "highPrecision", value = "true")
    @DependsOn(param = "engine", operator = ConditionOperator.NOT_EQUALS, value = "EEVEE")
    bounces: Int = 12
): String
```

#### Supported Operators (`ConditionOperator`):
- `EQUALS` (default), `NOT_EQUALS`
- `IN`, `NOT_IN`
- `GREATER_THAN`, `LESS_THAN`, `GREATER_OR_EQUAL`, `LESS_OR_EQUAL`
- `IS_BLANK`, `IS_NOT_BLANK`
- `REGEX_MATCH`

#### Logical Disjunction:
Use `@DependsOnAny` to specify logical OR:
```kotlin
@DependsOnAny(
    DependsOn(param = "model", value = "SDXL"),
    DependsOn(param = "model", value = "FLUX")
)
@CapabilityParam(description = "Refiner strength")
refinerStrength: Double = 0.8
```

#### Complex Object Dot Notation:
Target nested JSON properties using dot notation:
```kotlin
@DependsOn(param = "cloudConfig.provider", value = "aws")
@CapabilityParam(description = "AWS Region")
awsRegion: String? = null
```

## 4. Parameter Groups (`@ParameterGroup`)

Avoid long method signatures by grouping reusable capability parameters into `@Serializable data class` models.

### Mechanism:
1. **Compile-Time Manifest Unpacking**: KSP statically unpacks data class properties into individual parameters in the manifest (`manifest.json`).
2. **Transparent Dispatching**: The host application passes parameters individually; the generated dispatcher reconstructs the typed data class using `kotlinx.serialization`.
3. **Prefixing**: Use `prefix = "..."` to namespace parameters and prevent name collisions when reusing data classes.
4. **Inheritance**: Any `@DependsOn` or `isAdvanced` on the group is inherited by all member properties (combined via logical `AND`).

```kotlin
@Serializable
data class InferenceOptions(
    @CapabilityParam(description = "Temperature", defaultValue = "0.7")
    val temperature: Double = 0.7,

    @CapabilityParam(description = "Max Tokens", defaultValue = "2048", isAdvanced = true)
    val maxTokens: Int = 2048
)

@Capability(name = "Generate")
fun generate(
    @CapabilityParam(description = "Prompt") prompt: String,
    @ParameterGroup(prefix = "llm_") options: InferenceOptions = InferenceOptions()
): String
```

### Compiler Diagnostics & Rules:
- Classes used as `@ParameterGroup` **must** be annotated with `@Serializable`.
- Recursive data structures in parameter groups are forbidden (detected and rejected at compile time).
- Sibling conditions (e.g. `@DependsOn(param = "temperature")`) inside a prefixed group automatically resolve to the prefixed name (e.g. `llm_temperature`).
- Circular dependencies between parameters are detected via DFS cycle detection and reported as compile errors.

## 5. Complex Objects (`@ComplexObject`)

When passing rich domain objects between capabilities or flows:
1. Annotate the class with `@Serializable` and `@ComplexObject`.
2. Supply a namespaced `id` (e.g. `"my-plugin/BoundingBox"`), `description`, and `version`.
3. Deserialization is lenient: unknown fields in incoming JSON are automatically ignored without throwing errors.

```kotlin
@Serializable
@ComplexObject(id = "geo/BoundingBox", description = "2D Bounding Box", version = 1)
data class BoundingBox(val x: Int, val y: Int, val width: Int, val height: Int)
```

## 6. Capability Outputs & Multiple Return Pattern

### Single Output:
Annotate the function with `@CapabilityResult` to customize the default `"result"` output port:
```kotlin
@Capability(name = "Calculate Total")
@CapabilityResult(name = "totalAmount", description = "Sum with tax", semanticTypes = ["currency/usd"])
fun calculateTotal(subtotal: Double): Double = subtotal * 1.15
```

### Multiple Outputs:
Return a `@Serializable data class` where properties represent individual output ports:
```kotlin
@Serializable
data class DivisionResult(
    @CapabilityResult(name = "quotient", description = "Division quotient")
    val quotient: Int,
    @CapabilityResult(name = "remainder", description = "Division remainder")
    val remainder: Int
)

@Capability(name = "Divide")
fun divide(dividend: Int, divisor: Int): DivisionResult {
    return DivisionResult(dividend / divisor, dividend % divisor)
}
```

## 7. Changelog Management (`changelog.md`)

Place `changelog.md` in the root of the plugin module or `src/main/resources/changelog.md`. The KSP processor parses this file and embeds it into the plugin manifest.

### Standard Format:
```text
Version: 1.1.0
VersionName: Feature Update
Date: 2026-06-01
Added:
  - Added new image processing capability
Fixed:
  - Fixed memory leak in process watcher
----------------------------------------------------------------------------------------------------
Version: 1.0.0
VersionName: Initial Release
Date: 2026-05-01
Initial:
  - Initial public release
```

- Each block requires `Version:` and `Date:`.
- `VersionName:` is optional.
- Category headers (e.g. `Added:`, `Fixed:`, `Initial:`) must begin at the line start and end with `:`.
- Bullet points must be indented with at least one space and begin with `-`.
- Releases must be separated by 100 hyphens (`-`).
